# Templates plan: a selectable app, and starting points for new ones

- Status: implemented on 2026-09-17, reviewed by independent agents, and committed as `71cb04e`. Relay's and Coffer's baselines were accepted afterwards (see [Acceptance](#acceptance)).
- Scope: `STRUCTURAL_MAINTENANCE`, plus two new example packages. Relay's generated document must not change; its candidate hash moved only because the simulated layout became more faithful (see [Results](#results)).
- Decision: [ADR 0004](../adr/0004-selectable-apps-and-templates.md)

## Goal

After the [restructuring](./restructure-plan.md), a second design system or app still had to be copied by hand from Primer or Relay, and switching meant editing the plugin. This change lets an agent create a design system or an app from a template, switch the app the plugin builds with one command, and check every app, without any change to the plugin, the harness or the guards.

### Acceptance

On 2026-09-17 the maintainer reviewed Relay and Coffer in Figma Desktop and approved the candidate signatures above. A separate `BASELINE_ACCEPTANCE` task wrote the output of `design:signature` and `design:components`, unchanged, to `apps/relay/baselines/` and `apps/coffer/baselines/`. `pnpm each design:check` and `design:components:check` then passed for all five compositions, and the scope check saw only those four files. Until then, CI had failed at `design:check` on every push since the verification gate was added.

### Found while building the examples

- **Primer's starter row would have overflowed** by 17 px: its text column left room for one gap, but the spacer after it added a second gap and a pixel of its own. Nothing built it before the app template existed; the row no longer uses a spacer.
- **The renderer problem above surfaced with the first font tried for a second design system.** Source Sans 3's WOFF2 files name the family "Source Sans 3 ExtraLight", so the font check failed; the renderer fix then showed that no bundled font had ever been used for previews.
- **Wrapping rows were under-measured.** The simulated layout gave a wrapping row the height of its first line, so whatever followed was placed over its other lines. Only Primer's Octicons sheet wrapped onto a second line; its caption now sits below the grid, as it always did in Figma.
- **Figma keeps an empty auto-layout frame at its size**, 100 px tall for a new frame, where the simulated layout shrank it to nothing. A table header whose menu column has no title looked right offline but was drawn about 124 px tall in Figma instead of 42, which the review in Figma caught. The simulated layout now keeps the size, Carrara gives an empty cell a line's height, and its list components refuse an empty list.
- **Figma places every new node on the page.** Carrara's cards built an empty actions frame even when a card had no actions, and never appended it: 18 stray frames per build. The orphan rule ignored empty frames; it now reports every node that is never appended, and Relay and the templates have none.
- **Ellipses were drawn as rectangles** in PNG previews, so badge dots and chart markers looked square.
- **Stress cases found widths that went negative** at narrow sizes: the top bar's search at 360 px, a progress detail with a long bank name, a stat caption beside a long change. The shell folds its sidebar below 1024 px, and those components cap or move what does not fit.
- **State colours were chosen together.** The closest pair among positive, warning, critical, the accent and the comparison grey, warning and critical under deuteranopia, is 14.7 ΔE apart ([Carrara's ADR 0001](../../design-systems/carrara/docs/adr/0001-light-workspace-dark-sidebar.md)).
- **Stress results were never laid out or checked**, only built. Checking them found a state badge 5 px wider than its column in Coffer's payments table at 1280 px, and two gaps in Relay that only extreme data reaches: a release with no activity drew an empty timeline, which Figma keeps 100 px tall, and a very long name pushed an activity line 5 px past its box. Relay's pages now handle both without changing its normal output.
- **The out-of-frame check skipped every top-level frame that clips**, because it treated the frame itself as a hand-placed layer. Coffer's screens clip, so they were never checked; they pass now.
- **`pnpm audit` is pnpm's own security audit**, so the command in the docs and in `pnpm create:app`'s message never ran the harness. They now say `pnpm run audit`.
- **Two invented tax IDs were real**: an Irish VAT number and an Australian business number passed their national check digits and belonged to existing organisations. Every tax ID in Coffer now fails its country's check, and a test keeps it that way.
- **A space-between row with a bound gap** is untested territory in Figma, and Primer never uses one. Carrara's space-between rows keep a plain number instead.

### Review guide

- The whole change is commit `71cb04e`; `git show --stat 71cb04e` lists its files, and the baselines follow in their own commit.
- Suggested order: `figma-harness.config.json` and `packages/harness/src/core/workspace.ts`; `packages/harness/src/bundle/bundle.ts`, `build.ts` and `plugin/src/composition.ts`; `packages/contract/src/starter.ts`; `templates/`; `packages/cli/src/scaffold.ts`; the guards; `packages/harness/src/runtime/layout.ts`, `stress.ts`, `escapes.ts` and `rules/orphans.ts`, and `packages/engine/src/layout-lint.ts`; then Carrara and Coffer as a user of all of it; then the docs.
- To try it: `pnpm use`, `pnpm use coffer`, run the plugin in Figma, then `pnpm use relay` to come back.

### Not done

- Moving an existing app to another design system has no command: it changes the app's pages, so it stays a reviewed change.
- Two Figma behaviours are not documented and cannot be checked offline: whether `resize()` keeps a size variable, and how a space-between row treats a bound gap. Carrara avoids depending on either.
- The simulated layout aligns `BASELINE` rows to the top, which only changes how amount cells look in previews.
